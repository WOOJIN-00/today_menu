# 🍳 오늘 뭐 먹지? — AI 메뉴 추천기

냉장고에 있는 재료를 고르면 AI가 지금 만들 수 있는 메뉴 3개와 간단한 레시피를 추천해 주는 웹앱입니다.
매번 "오늘 뭐 먹지?"를 고민하는 자취생·1인 가구가 남은 재료로 장보기 비용을 줄이도록 돕는 것이 목표입니다.

- AI(Google Gemini)가 입력할 때마다 새로 추천합니다.
- AI 호출이 실패하거나 무료 한도가 차면 **기본 레시피 39개**에서 자동으로 추천해, 앱이 멈추지 않습니다.
- 결과 카드에는 출처가 **🤖 AI 추천** 또는 **📖 기본 레시피**로 표시됩니다.

## 사용법 (3단계)

1. **재료 고르기**: 가지고 있는 재료 칩을 누르세요. 목록에 없으면 직접 입력해 추가할 수 있습니다. (최대 15개)
   기분·상황(빠르게, 든든하게, 매콤하게 등)은 선택 사항입니다.
2. **추천받기**: 버튼을 누르면 메뉴 3개가 나옵니다.
3. **레시피 확인**: 카드에서 조리 시간, 부족한 재료, 단계별 레시피를 바로 볼 수 있습니다.

그 밖의 기능:
- **🔄 다시 추천**: 이미 나온 메뉴는 빼고 새로 추천합니다.
- **⭐ 즐겨찾기**: 카드의 ☆를 눌러 저장하고, 오른쪽 위 버튼으로 목록을 봅니다. (이 브라우저에만 저장됩니다)

> 소금·간장·고추장·식용유 같은 기본 양념은 집에 있다고 가정합니다.
> AI 추천은 조리 전 재료와 익힘 정도를 꼭 확인하세요.

## 구조

```
├─ index.html        화면 (HTML·CSS·JS 한 파일, 프레임워크 없음)
├─ recipes.js        기본 레시피 39개 + 재료 일치 기반 추천 함수 (대체 경로)
├─ api/recommend.js  Vercel 서버 함수: 입력 검사 → 캐시 → 횟수 제한 → Gemini 호출·검증 → 실패 시 대체
├─ vercel.json       Vercel 설정 (최소)
└─ Plan.md           계획 설계서
```

```
브라우저(index.html)
   │  재료·기분·이미 나온 메뉴 전송 (POST /api/recommend)
   ▼
서버 함수(api/recommend.js)  ← API 키는 환경변수에만 보관
   │  ① 입력 검사  ② 캐시 확인  ③ IP별 횟수 확인
   │  ④ Gemini에 후보 5개 요청 → 형식 검증, 이미 나온 메뉴·중복 걸러내고 앞에서 3개 사용
   │     (새 메뉴가 0개면 "이미 나온 메뉴 목록"을 다시 적은 프롬프트로 1회 재시도)
   │  키 없음·한도 초과·오류 시
   └─▶ recipes.js 기본 레시피에서 추천 (고른 재료와 겹치는 메뉴만)
   ▼
브라우저에 결과 표시 ("AI 추천" / "기본 레시피")
```

서버 응답 형식:

```json
{
  "source": "ai",
  "menus": [
    { "name": "메뉴 이름", "time_min": 15, "ingredients": ["재료1"], "missing": ["부족한 재료"], "steps": ["1단계"] }
  ]
}
```

- 메뉴가 3개보다 적으면 `"partial": true`가 붙습니다. (화면에 "AI가 새로 찾은 메뉴는 N개예요" 등 안내)
- 기본 레시피로 응답할 때는 `"source": "fallback"`과 함께 이유를 알려 주는 `reason`이 붙습니다.
  `no_key`(키 없음), `daily_limit`(하루 횟수 초과), `ai_quota`(Gemini 한도 초과), `ai_error`(AI 오류·검증 실패), `server_error`(예상치 못한 오류).
- 기본 레시피 중 고른 재료와 겹치는 메뉴가 하나도 없으면 `"reason": "no_match"`, `"menus": []`로 응답합니다.
  - AI를 쓰지 못해 대체 경로로 왔다면 그 이유를 `cause`에 담습니다. (예: `{"source":"fallback","reason":"no_match","cause":"ai_error","menus":[]}`)
    → 화면: "AI가 지금 바빠서 새 메뉴를 가져오지 못했어요. 잠시 뒤 다시 눌러 주세요."
  - AI는 정상 응답했지만 새 메뉴가 0개였다면(후보가 모두 이미 나온 메뉴) `cause`가 없습니다.
    → 화면: "이 재료로 더 추천할 새 메뉴를 못 찾았어요. 재료를 더 추가하거나 처음부터 다시 추천받아 보세요."

## 로컬 실행 방법

**화면만 빠르게 보기**: `index.html`을 더블클릭해 브라우저로 엽니다.
서버가 없으므로 "서버에 연결하지 못했어요" 안내와 함께 기본 레시피로 동작합니다.

**서버 함수까지 실행하기** (Node.js 필요):

```bash
npx vercel dev
```

처음 실행하면 Vercel 로그인과 프로젝트 연결을 묻습니다. 실행 후 `http://localhost:3000`을 엽니다.
AI 추천까지 확인하려면 아래 환경변수를 `.env.local` 파일에 넣습니다. (`.env*` 파일은 `.gitignore`로 GitHub에 올라가지 않습니다)

## 환경변수

| 이름 | 필수 | 설명 |
|---|---|---|
| `GEMINI_API_KEY` | 선택 | Google AI Studio에서 발급한 Gemini API 키. 없으면 기본 레시피로만 동작합니다. |
| `GEMINI_MODEL` | 선택 | 사용할 Gemini 모델 이름. 비워 두면 `gemini-3.8-flash`를 사용합니다. |
| `GEMINI_FALLBACK_MODEL` | 선택 | 기본 모델이 과부하(503)로 두 번 실패하면 한 번 더 시도할 예비 모델 이름 (예: 무료 등급의 다른 flash 모델). 비워 두면 이 단계를 건너뜁니다. |

- 키는 **서버 함수에서만** 읽습니다. 화면 코드나 GitHub에는 절대 넣지 않습니다.
- 배포 시에는 Vercel 프로젝트의 **Settings → Environment Variables**에 등록합니다.
- 키를 발급할 때 **결제(Billing)를 설정하지 않습니다.** 무료 등급은 한도를 넘으면 요금이 아니라 오류로 멈춥니다.
- 무료 한도 수치는 수시로 바뀌므로, 키 발급 시점에 Google AI Studio 화면에서 확인하세요.

## 무료 한도 보호 방식

| 장치 | 내용 |
|---|---|
| IP별 횟수 제한 | 한 IP당 하루 AI 요청 20회. 넘으면 기본 레시피로 응답 |
| 결과 캐시 | 같은 재료·기분·제외 메뉴 조합은 10분 동안 저장한 결과를 재사용 (AI 호출·횟수 차감 없음). 재료 순서·앞뒤 공백·대소문자·중복이 달라도 같은 조합으로 인식 |
| 입력 제한 | 재료 1~15개, 항목당 20자 이하. 기분은 정해진 값만. 이상하면 400 응답 |
| 시간 제한 | AI 대기는 한 번에 최대 10초, 재시도·예비 모델 포함 전체 14초 → 응답은 항상 15초 안에. 남은 시간이 3초 미만이면 재시도 없이 기본 레시피 |
| 재시도 최소화 | 기본 모델은 1회만 재시도. 과부하(503)면 1.5초 쉬고 재시도, 그래도 503이면 예비 모델(`GEMINI_FALLBACK_MODEL`)로 1회. 한도 초과(429)·시간 초과는 재시도하지 않음 |
| 대체 경로 | 키 없음·한도 초과·오류 시 기본 레시피로 자동 전환 |
| 개인정보 제외 | AI에는 재료·기분·제외 메뉴만 보냄 |

## 한계와 다음 계획

### 1. 메모리 방식 제한의 한계
IP별 하루 20회 제한과 결과 캐시는 서버 함수의 메모리에 저장합니다. 그래서 다음 경우에는 정확하지 않습니다.
- 사용자가 몰려 Vercel이 서버 함수를 여러 개 동시에 띄우면, 각자 따로 횟수를 세므로 20회보다 더 쓸 수 있습니다.
- 한동안 요청이 없어 서버 함수가 꺼졌다 다시 켜지면, 횟수와 캐시가 모두 초기화됩니다.
- 같은 와이파이 사용자는 IP가 같아 횟수를 나눠 쓰고, IP를 바꾸면 제한을 피할 수 있습니다.

### 2. 그래도 문제가 크지 않은 이유
- Google AI Studio에 결제를 설정하지 않았기 때문에 한도를 넘어도 요금이 나오지 않고 오류(429)만 납니다.
- 429나 다른 오류가 나면 기본 레시피 39개로 자동 전환되므로 앱은 멈추지 않습니다. 화면에는 "기본 레시피"로 표시됩니다.

### 3. 그 밖의 한계
- 기본 레시피는 39개뿐이라, 특이한 재료(예: 단호박)만 고르고 AI가 실패하면 추천할 메뉴가 없을 수 있습니다.
  이때는 엉뚱한 메뉴를 채우지 않고 "재료를 더 추가하거나 처음부터 다시 추천받아 보세요"라고 안내합니다.
- 재료가 하나뿐이면 "다시 추천"을 거듭할수록 AI가 새로 찾는 메뉴가 줄어 3개보다 적게 나올 수 있습니다.
- "다시 추천"은 이미 나온 메뉴를 최대 60개까지 기억합니다. 그 이상은 추천받기를 눌러 처음부터 시작합니다.
- 즐겨찾기는 브라우저 저장소(localStorage)에 저장되므로 다른 기기와 공유되지 않습니다.
- AI가 엉뚱하거나 부정확한 레시피를 낼 수 있어, AI 추천에는 조리 전 확인 안내를 표시합니다.

### 4. 다음 계획
사용자가 늘어 정확한 제한이 필요해지면, 횟수와 캐시를 Upstash Redis 같은 공용 저장소로 옮겨 모든 서버 함수가 같은 값을 보도록 바꿀 계획입니다.
